# 入荷一覧画面 (`/fi/intake/list`) 仕様書

## 概要

入荷データの一覧表示とバーコードスキャンによる出荷処理を行う画面です。

**URL**: `/fi/intake/list`  
**ルーティング**: `factory_shipping/intake/views.py` の `list_items()` 関数  
**テンプレート**: `templates/intake/list.html`  
**認証**: ログイン必須 (`@login_required`)

---

## 機能一覧

### 1. 入荷データ一覧表示
- タグ番号が空でない入荷データを一覧表示
- ページネーション対応（デフォルト: 50件/ページ）
- ソート機能（預かり日、タグ番号）
- 検索・フィルタ機能

### 2. バーコードスキャン出荷処理
- HIDバーコードリーダーからの自動検出
- 9桁バーコードの直接入力
- 手動入力（店舗コード + タグ番号）

### 3. 出荷状態管理
- 出荷済み/未出荷の切り替え（クリック操作）
- 出荷日時の記録

### 4. データ未取得チェック
- 過去7日間のデータ未取得を検出・表示

---

#### 検索条件の詳細

##### 1. 基本フィルタ（常に適用）

**タグ番号が空でないレコードのみ表示**
- 条件: `tag_number != '' AND tag_number IS NOT NULL`
- 目的: 有効な入荷データのみを表示
- 除外されるデータ: タグ番号が空文字またはNULLのレコード

---

##### 2. 店舗コードフィルタ (`store_code`)

**入力形式**:
- 2桁: `"02"`, `"24"` など
- 4桁: `"0002"`, `"0024"` など

**正規化処理**:
1. 前後の空白を削除（`strip()`）
2. 2桁の数字の場合:
   - 左側に `"00"` を追加して4桁に変換
   - 例: `"02"` → `"0002"`, `"24"` → `"0024"`
3. 4桁の場合はそのまま使用

**検索方法**:
- **完全一致検索**（`IntakeItem.store_code == store_code`）
- 正規化後の店舗コードと完全一致するレコードのみ表示

**使用例**:
```
store_code=02    → 0002 で検索
store_code=0024  → 0024 で検索
store_code=      → フィルタなし（全店舗）
```

**UI表示**:
- セレクトボックスで選択可能
- 表示形式: `{店舗コード下2桁} - {店舗名}`（例: `24 - 秋川店`）
- 選択値: 4桁の店舗コード（例: `0024`）

---

##### 3. タグ番号フィルタ (`tag_number`)

**入力形式**:
- `0-000` 形式: `"0-123"`, `"4-212"` など
- 4桁数字: `"0123"`, `"4212"` など

**正規化処理**:

**パターンA: ハイフンを含む場合（`0-000`形式）**
1. ハイフンで分割: `parts = tag_number.split('-')`
2. 左側と右側が数字かチェック
3. 左側を2桁にパディング（`zfill(2)`）
   - 例: `"0-123"` → `"00-123"`
   - 例: `"4-212"` → `"04-212"`（ただし、実際のDBには `"4-212"` 形式で保存されている可能性あり）

**パターンB: ハイフンを含まない場合（4桁数字）**
1. 4桁の数字かチェック
2. 先頭1桁と残り3桁に分割
3. `X-YYY` 形式に変換
4. 左側を2桁にパディング（`zfill(2)`）
   - 例: `"0123"` → `"0-123"` → `"00-123"`
   - 例: `"4212"` → `"4-212"` → `"04-212"`

**パターンC: その他の形式**
- 正規化できない場合は、入力値をそのまま使用

**検索方法**:
- **部分一致検索**（`LIKE '%{tag_search}%'`）
- 正規化後の文字列を含むタグ番号を検索

**使用例**:
```
tag_number=0-123     → "00-123" を含むタグを検索
tag_number=0123      → "00123" を含むタグを検索
tag_number=4-212     → "04-212" を含むタグを検索（実際は "4-212" もマッチ）
tag_number=          → フィルタなし
```

**注意事項**:
- タグ番号のDB保存形式は `"4-212"` または `"4212"` の可能性がある
- 表示形式は `get_formatted_tag_number()` で `"0-123"` 形式に変換される
- 部分一致検索のため、複数のタグがマッチする可能性がある

---

##### 4. 預かり日フィルタ (`date_from`, `date_to`)

**入力形式**:
- `YYYY-MM-DD` 形式のみ（例: `"2024-01-15"`）
- HTML5の `date` 入力タイプを使用

**検索方法**:

**`date_from`（開始日）**:
- 条件: `intake_date >= date_from`
- 指定日を含む未来の日付を検索
- 例: `date_from=2024-01-15` → 2024年1月15日以降のデータ

**`date_to`（終了日）**:
- 条件: `intake_date <= date_to`
- 指定日を含む過去の日付を検索
- 例: `date_to=2024-01-31` → 2024年1月31日以前のデータ

**範囲指定**:
- 両方を指定した場合: `date_from <= intake_date <= date_to`
- 例: `date_from=2024-01-15&date_to=2024-01-31` → 2024年1月15日〜31日のデータ

**エラーハンドリング**:
- 日付形式が不正な場合:
  - `ValueError` が発生
  - 警告メッセージをフラッシュ表示
  - 該当フィルタを無視して検索を継続

**使用例**:
```
date_from=2024-01-01           → 2024年1月1日以降
date_to=2024-01-31             → 2024年1月31日以前
date_from=2024-01-01&date_to=2024-01-31  → 2024年1月のデータ
date_from=invalid              → エラー、フィルタ無視
```

---

##### 5. 出荷状態フィルタ (`status`)

**選択肢**:
- `'unshipped'`: 未出荷のみ表示
- `'all'`: 全て表示（デフォルト）

**検索方法**:

**`status='unshipped'`**:
- 条件: `is_shipped == False`
- 未出荷のレコードのみ表示

**`status='all'`**:
- フィルタなし
- 出荷済み・未出荷の両方を表示

**使用例**:
```
status=unshipped  → 未出荷のみ
status=all        → 全て（デフォルト）
```

**UI表示**:
- セレクトボックスで選択可能
- 選択肢:
  - `未出荷のみ` → `status=unshipped`
  - `全て` → `status=all`

---

##### 6. ソート機能 (`sort_by`, `sort_order`)

**ソート項目** (`sort_by`):
- `'intake_date'`: 預かり日でソート（デフォルト）
- `'tag_number'`: タグ番号でソート

**ソート順** (`sort_order`):
- `'asc'`: 昇順（デフォルト）
- `'desc'`: 降順

**ソート実装**:

**預かり日ソート** (`sort_by='intake_date'`):
- 昇順: `ORDER BY intake_date ASC, id ASC`
- 降順: `ORDER BY intake_date DESC, id DESC`
- セカンダリソート: `id`（同じ預かり日の場合はID順）

**タグ番号ソート** (`sort_by='tag_number'`):
- 昇順: `ORDER BY tag_number ASC, id ASC`
- 降順: `ORDER BY tag_number DESC, id DESC`
- セカンダリソート: `id`（同じタグ番号の場合はID順）

**UI操作**:
- テーブルヘッダーをクリックでソート切り替え
- 同じカラムをクリック: 昇順 ↔ 降順を切り替え
- 異なるカラムをクリック: 昇順から開始
- ソートアイコン表示:
  - `▲`: 昇順でソート中
  - `▼`: 降順でソート中
  - `⇅`: ソート未適用

**使用例**:
```
sort_by=intake_date&sort_order=asc   → 預かり日昇順
sort_by=intake_date&sort_order=desc  → 預かり日降順
sort_by=tag_number&sort_order=asc   → タグ番号昇順
```

##### 7. ページネーション (`page`, `per_page`)

**ページ番号** (`page`):
- 型: integer
- デフォルト: `1`
- 範囲: 1以上
- 最大ページ数は検索結果に応じて自動計算

**表示件数** (`per_page`):
- 型: integer
- デフォルト: `50`
- 選択肢: `25`, `50`, `100`, `200`

**ページネーション情報**:
- `pagination.total`: 総件数
- `pagination.page`: 現在のページ番号
- `pagination.pages`: 総ページ数
- `pagination.has_prev`: 前のページがあるか
- `pagination.has_next`: 次のページがあるか
- `pagination.prev_num`: 前のページ番号
- `pagination.next_num`: 次のページ番号

**ページネーション表示**:
- 前へ/次へボタン
- ページ番号リンク（左右2ページずつ表示）
- 検索条件を保持したままページ遷移

**使用例**:
```
page=1&per_page=50    → 1ページ目、50件/ページ
page=2&per_page=100   → 2ページ目、100件/ページ
```

##### 8. ハイライト表示 (`highlight_tag`)

**用途**:
- バーコードスキャン成功時に該当行をハイライト表示
- 表示専用パラメータ（検索には影響しない）

**形式**:
- `0-000` 形式（例: `"0-123"`）
- `get_formatted_tag_number()` の戻り値と同じ形式

**動作**:
1. URLパラメータから `highlight_tag` を取得
2. テーブル内で該当タグ番号の行を検索
3. スムーズスクロールで該当行まで移動
4. 2秒間黄色背景（`#fff3cd`）でフラッシュ表示
5. URLパラメータから削除（リロード時に再度ハイライトされないように）

**使用例**:
```
highlight_tag=0-123  → タグ番号 "0-123" の行をハイライト
```

#### 検索条件の組み合わせ

**複数条件の適用順序**:
1. 基本フィルタ（タグ番号が空でない）
2. 店舗コードフィルタ
3. タグ番号フィルタ
4. 預かり日フィルタ（from/to）
5. 出荷状態フィルタ
6. ソート
7. ページネーション

**AND条件**:
- すべての検索条件は AND 条件で結合される
- 例: `store_code=0024&status=unshipped&date_from=2024-01-01` → 店舗0024、未出荷、2024年1月1日以降のデータ

**条件の保持**:
- 検索後も検索条件はフォームに保持される
- ページネーション時も検索条件を維持
- URLパラメータとして保持されるため、ブックマーク可能

### POST リクエスト

#### バーコード出荷処理

**フォームデータ**:
- `scanned_code` (string): 9桁のバーコード

**処理フロー**:
1. バーコードをパース（`parse_tag_barcode()`）
   - 1-3桁目: 店舗コード（3桁）
   - 4桁目: チェックデジット（無視）
   - 5-8桁目: タグ番号（4桁）
   - 9桁目: チェックデジット（無視）
2. 店舗コードを4桁に変換
3. タグ番号を `X-YYY` 形式に変換（例: `"4212"` → `"4-212"`）
4. 未出荷の入荷データを検索
5. 見つかった場合:
   - `is_shipped = True` に更新
   - `shipped_at` に現在日時を設定
   - `ShipmentLog` を作成
6. 成功時: GET にリダイレクト（PRGパターン）
7. 失敗時: エラーメッセージを表示

**レスポンス**:
- 成功時: GET にリダイレクト（`highlight_tag` パラメータ付き）
- 失敗時: エラーメッセージをフラッシュして GET にリダイレクト

## バーコード仕様

### NW-7形式（9桁）

**構成**:
```
[店舗コード3桁][チェック1桁][タグ4桁][チェック1桁]
```

**例**:
- バーコード: `024642123`
  - 店舗コード: `024` → `0024`（4桁に変換）
  - タグ番号: `4212` → `4-212`（表示形式）

### 手動入力時のバーコード生成

手動入力フォームから送信される場合、以下のルールでバーコードを生成:

1. 店舗コードの後ろ3桁を取得（例: `"0024"` → `"024"`）
2. 店舗コードの4桁目をチェックデジット1として使用
3. タグ番号4桁をそのまま使用
4. タグ番号の先頭1桁をチェックデジット2として使用

**例**:
- 店舗コード: `0024`
- タグ番号: `0123`
- 生成バーコード: `024401231`（`024` + `4` + `0123` + `1`）

## JavaScript機能

### 1. グローバルバーコードスキャナー検出

**動作**:
- 入力欄にフォーカスがない状態で数字キーを検出
- 50ms以内の連続入力はスキャナーからの入力と判定
- 9桁に達すると自動送信
- Enterキーでも送信可能（9桁未満でも処理）

**バッファ管理**:
- 3秒間入力がない場合、バッファをリセット
- バッファ内容を画面上部に表示

### 2. 手動入力フォーム処理

- タグ番号入力欄は数字のみ許可
- 4桁入力時に自動的にバーコードを生成して送信
- バーコード生成ロジック:
  ```
  店舗コード後ろ3桁 + 店舗コード4桁目 + タグ4桁 + タグ先頭1桁
  ```

### 3. ソート切り替え

- テーブルヘッダークリックでソート
- 同じカラムをクリック: 昇順/降順を切り替え
- 異なるカラムをクリック: 昇順から開始
- ページ番号を1にリセット

### 4. 出荷状態トグル

- バッジクリックで出荷状態を切り替え
- AJAXリクエストで非同期更新
- 成功時: バッジと行スタイルを更新
- 失敗時: エラーメッセージを表示

**エンドポイント**: `/fi/intake/toggle-shipment/<item_id>` (POST)

### 5. ハイライト表示

- バーコードスキャン成功時、該当行をハイライト
- URLパラメータ `highlight_tag` で指定
- スムーズスクロールで該当行まで移動
- 2秒間黄色背景でフラッシュ表示

## データモデル

### IntakeItem（入荷データ）

**主要フィールド**:
- `id`: 主キー
- `store_id`: 店舗ID（FK）
- `store_code`: 店舗コード（4桁、例: "0024"）
- `store_name`: 店舗名
- `tag_number`: タグ番号（DB形式: "4-212" または "4212"）
- `intake_date`: 預かり日（DATE型）
- `product_name`: 商品名
- `customer_name`: 顧客名
- `is_shipped`: 出荷済みフラグ（BOOLEAN）
- `shipped_at`: 出荷日時（DATETIME型、NULL可）
- `imported_at`: CSV取り込み日時

**メソッド**:
- `get_formatted_tag_number()`: タグ番号を `0-000` 形式で返す

### ShipmentLog（出荷ログ）

**主要フィールド**:
- `id`: 主キー
- `intake_item_id`: 入荷データID（FK）
- `store_id`: 店舗ID（FK）
- `scanned_code`: スキャンされたバーコード（9桁）
- `scanned_at`: スキャン日時
- `scanned_by_user_id`: スキャン実行ユーザーID（FK）
- `status`: ステータス（'completed', 'error' など）

## エラーハンドリング

### バーコード処理エラー

| エラー | メッセージ | 処理 |
|-------|----------|------|
| バーコード形式不正 | `バーコードの形式が正しくありません: {詳細}` | 警告メッセージ表示 |
| 店舗未検出 | `該当する店舗が見つかりません（店舗コード: {code}）` | 警告メッセージ表示 |
| データ未検出 | `該当する入荷データが見つかりません（店舗: {code} / タグ: {tag}）` | 警告メッセージ表示 |

| エラー | メッセージ | 処理 |
|-------|----------|------|
| 日付形式不正 | `日付（from/to）の形式が正しくありません` | 警告メッセージ表示、該当フィルタを無視 |

## セキュリティ

### 認証・認可

- ログイン必須（`@login_required` デコレータ）
- 出荷処理時にユーザー情報を記録（`ShipmentLog.scanned_by_user_id`）

### 入力検証

- バーコード: 9桁数字のみ許可
- タグ番号: 数字のみ許可（手動入力時）
- 日付: YYYY-MM-DD形式のみ許可
- SQLインジェクション対策: SQLAlchemy ORM使用

## 備考

- タグ番号の表示形式とDB保存形式が異なる場合がある
  - 表示: `0-123`（先頭1桁を除去した形式）
  - DB: `4-212` または `4212`（元の形式）
- バーコードスキャンはHIDデバイスとして認識されるバーコードリーダーに対応
- 手動入力時はバーコードを自動生成して送信するため、バーコードリーダーがなくても出荷処理可能
